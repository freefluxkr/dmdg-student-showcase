﻿NotebookLM 발표 소스 / 한국어 / 총 11장 / 현재 완성된 실험 시스템 설명
발표 방향: 설계 목적 → 구조 → 데이터 → 개별 분석 → 결합 모델 → 근거 설명 → 웹 구현 → 평가 → 결론의 흐름으로 구성한다. 개발 도중의 변경 이력은 다루지 않는다. 기능 구현 사실과 관측 성능을 구분한다. 실제 결합 모델은 웹 기본 예측에 사용 중이며 운영 안전성을 입증한 모델이라는 뜻은 아니다.
시각화 원칙: 실제 자료가 없는 화면·기여도·패턴 위치·성능 수치는 만들지 않는다. 본문은 짧게, 발표자 설명과 작성 주의사항은 참고 정보로 사용한다.

3장. 파일 업로드 → 개별 분석 → 결합 예측 → 근거 설명

핵심 메시지:
원본 파일의 두 분석 결과를 후단 결합 모델에 입력한다.

슬라이드 내용:
1. EXE/DLL 업로드
2. 확장자·크기·PE 구조·지원 유형 검사
3-A. EMBER 원시 피처 → 528개 벡터 → LightGBM 점수·피처 기여도
3-B. YARA-X → 규칙 매칭 여부·규칙명·패턴 위치
4. 결합 입력: LightGBM 점수 + YARA-X 매칭 여부(0/1)
5. 로지스틱 회귀 → 결합 점수 → 임계값 0.5 예측
6. 대시보드 표시·JSON 보고서 다운로드
검사 실패: 판정 불가, 개별 점수로 자동 대체하지 않음

추천 시각 자료:
입력 검사 뒤 두 갈래로 분리하고 로지스틱 회귀에서 합쳐지는 구조도로 표현한다. LightGBM 기여도와 YARA 근거는 대시보드로 직접 연결하는 보조선을 그린다.

발표자 설명:
YARA 결과를 LightGBM의 528개 입력에 추가한 구조는 아닙니다. LightGBM은 원래 입력을 그대로 사용하고, 그 점수와 YARA 매칭 여부가 별도의 로지스틱 회귀로 들어갑니다. 두 갈래 그림은 기능 경로를 뜻하며 병렬 실행을 의미하지 않습니다.

작성 주의사항:
528개 LightGBM 입력을 530개로 표시하지 않는다. 동적 실행·격리·자동 삭제 기능을 넣지 않는다.
