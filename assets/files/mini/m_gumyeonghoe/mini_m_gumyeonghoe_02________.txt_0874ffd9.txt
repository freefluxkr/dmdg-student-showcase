발표 방향: 설계 목적 → 구조 → 데이터 → 개별 분석 → 결합 모델 → 근거 설명 → 웹 구현 → 평가 → 결론의 흐름으로 구성한다. 개발 도중의 변경 이력은 다루지 않는다. 기능 구현 사실과 관측 성능을 구분한다. 실제 결합 모델은 웹 기본 예측에 사용 중이며 운영 안전성을 입증한 모델이라는 뜻은 아니다.
시각화 원칙: 실제 자료가 없는 화면·기여도·패턴 위치·성능 수치는 만들지 않는다. 본문은 짧게, 발표자 설명과 작성 주의사항은 참고 정보로 사용한다.

2장. 숫자만 보여주는 탐지에서 근거를 함께 확인하는 분석으로

핵심 메시지:
파일에 대한 예측과 그 판단 근거를 함께 제공한다.

슬라이드 내용:
문제:
- 모델 점수만으로는 사용자가 이유를 이해하기 어려움
- 통계적 특징 분석과 규칙 검사는 각각 탐지 범위와 한계가 있음
- 분석 실패와 미탐지를 구분해야 함
설계 목표:
- 모델·규칙 결과를 결합해 일관된 예측 제공
- 개별 결과와 근거를 남겨 사람이 검토할 수 있게 구성
- 오류를 정상으로 취급하지 않고 판정 불가로 처리

추천 시각 자료:
점수만 있는 카드와 점수·근거·검사 상태를 함께 보여주는 카드 두 개를 대비한다. 수치가 필요하면 설명용 예시라고 표시한다.

발표자 설명:
LightGBM은 학습한 특징의 관계로 점수를 내고 YARA-X는 정해진 패턴을 검사합니다. 두 정보의 관계를 결합 모델로 학습하되, 사용자에게 결과 하나만 제시하지 않습니다. 특징 기여도와 규칙 근거를 함께 보여주어 판단을 검토할 수 있게 하는 것이 핵심입니다.

작성 주의사항:
두 도구가 항상 서로의 오류를 보완한다고 가정하지 않는다. 모델 점수를 실제 악성 확률로 표현하지 않는다.
